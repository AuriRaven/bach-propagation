# CONTEXT.md — Bach Propagation

> Last updated: 2026-03-08

---

## 1. What the project is

**Bach Propagation** is a music-analysis and machine-learning research pipeline whose goal is to computationally study and model the harmonic language of J.S. Bach. It takes raw MIDI or MusicXML scores, runs them through a multi-stage symbolic analysis pipeline to extract structured harmonic sequences, trains a baseline sequence model on those sequences, and then probes the learned representations with unsupervised techniques to test how well the model has internalized tonal structure.

The project is intended as the backbone of a thesis/research project. All code is in Python 3.11+, managed with [uv](https://github.com/astral-sh/uv).

---

## 2. High-level pipeline

```
MIDI / MusicXML
      │
      ▼
  ScoreLoader          ← parse to internal Score representation
      │
      ▼
  Quantizer            ← snap onsets/durations to rhythmic grid
      │
      ▼
  Windower             ← segment into analysis windows
      │
      ▼
  KeyEstimator         ← global & local key detection (Krumhansl-Schmuckler)
      │
      ▼
  ChordClassifier      ← template-matching chord detection (geometric-mean scoring)
      │
      ▼
  RomanNumeralAnalyzer ← (Chord, KeyEstimate) → RomanNumeral (with secondary dominants)
      │
      ▼
  FunctionLabeler      ← T / PD / D labeling with contextual overrides
      │
      ▼
  ProlongationAnalyzer ← 3-level Schenkerian reduction tree
      │
      ▼
  SequenceExtractor    ← encode harmonic events → integer token sequences
      │
      ▼
  BaroqueHarmonyLSTM   ← next-chord prediction model (trained)
      │
      ▼
  EmbeddingAnalysis    ← unsupervised analysis of learned chord embedding space
```

## 4. Module-by-module detail

### 4.1 Core (`src/core/`)

**`data_structures.py`** — All musical domain types. Key classes:

| Class | Purpose |
|---|---|
| `MusicalEvent` | Single note/rest. Fields: `pitch`, `onset`, `duration`, `velocity`, `measure`, `beat`, `beat_strength`, `voice`, `is_rest`. |
| `Chord` | Detected chord. Fields: `onset`, `duration`, `root` (0–11), `quality`, `pitches`, `bass`, `inversion`. |
| `HarmonicEvent` | Bundles `Chord` + `RomanNumeral`; single addressable event for prolongation. |
| `RomanNumeral` | Roman-numeral label in a key. Fields: `degree`, `quality`, `inversion`, `local_key_tonic`, `local_key_mode`, `is_secondary`, `secondary_target`, `function`. Renders via `.label` (e.g. `"V7/V"`, `"viio6"`). |
| `KeyEstimate` | Estimated key: `tonic`, `mode`, `confidence`, `onset`. `.label` → e.g. `"G major"`. |
| `HarmonicSegment` | Time-bounded tonal section with chords and roman numerals. |
| `Score` | Complete score: `events`, `time_signatures`, `title`, `composer`, `tempo`. |
| `HarmonicFunction` | Enum: `TONIC`, `PREDOMINANT`, `DOMINANT`, `AMBIGUOUS`. |
| `ProlongationLevel` | Enum: `FOREGROUND`, `MIDDLEGROUND`, `BACKGROUND`. |

All temporal values (`onset`, `duration`, `beat`) use `fractions.Fraction` — no floating-point rounding errors in rhythmic arithmetic.

**`score_loader.py`** — Converts MIDI/MusicXML to `Score`. Key methods:
- `ScoreLoader.load(path)` — load from a local file path.
- `ScoreLoader.load_corpus(bwv)` — load from music21's built-in corpus (no local file needed).
- `ScoreLoader.load_from_m21(m21_score)` — wrap a pre-parsed music21 Score.
- Constructor param `separate_voices=False` flattens all MIDI tracks to voice 0 (needed for MuseScore-exported solo MIDI, which creates 3–4 tracks even for monophonic pieces).

---

### 4.2 Temporal (`src/temporal/`)

**`meter_analyzer.py`** — Builds hierarchical metric weight grids from a `TimeSignature`. Returns a `MetricGrid` whose `.weight_at(beat_pos: Fraction)` gives a [0.0, 1.0] weight for any beat position. Downbeats → 1.0.

**`quantizer.py`** — Snaps event onsets and durations to a rhythmic grid (default: 1/16 note resolution) to correct MIDI timing imprecision.

**`windower.py`** — Segments a `Score` into overlapping or non-overlapping windows (by measure, by beat, or sliding). Produces `List[List[MusicalEvent]]` for downstream harmonic analysis.

---

### 4.3 Harmonic (`src/harmonic/`)

**`key_estimator.py`** — Implements the Krumhansl-Schmuckler algorithm. Correlates the pitch-class distribution of a window with major and minor key profiles to estimate the most likely key. Returns a `KeyEstimate`.

**`chord_classifier.py`** — Template-matching chord detection. Scores candidate chords against the pitch classes present in a window using a geometric-mean formula:

```
score = raw_matches / sqrt(total_pitches × n_template_tones)
```

This balances coverage (all notes explained) and completeness (all template tones present). Seventh chords win only when all four notes are present; missing template tones are penalised.

**`roman_numeral_analyzer.py`** — Takes a `Chord` and a `KeyEstimate` and produces a `RomanNumeral`. Detects secondary dominants: an event is marked `V/x` only when `(chord.root + 5) % 12` matches a diatonic tonic and the chord quality differs from the expected diatonic quality for that degree.

**`function_labeler.py`** — Labels each `RomanNumeral` with a `HarmonicFunction` (T / PD / D). Uses rule-based heuristics with contextual overrides (e.g. a predominant IV immediately before a V is kept as PD even if metric context might suggest otherwise).

---

### 4.4 Schenkerian (`src/schenkerian/`)

**`prolongation.py`** — Implements a three-level structural reduction inspired by Schenkerian analysis.

**Levels:**
- Level 0 — **Foreground**: all harmonic events.
- Level 1 — **Middleground**: foreground after passing, neighbor, and arpeggiation reduction.
- Level 2 — **Background** (Ursatz skeleton): middleground after neighbor and arpeggiation reduction.

**Reduction rules:**
- **Passing**: remove event X between A and B if X shares harmonic function with A or B and bass moves stepwise (≤ 2 semitones) A→X→B.
- **Neighbor**: remove X between A and B if A and B share the same chord root and X departs from it.
- **Arpeggiation**: remove X if it shares the same chord root as the previous event but in a different inversion.

**Constraints:**
- Cadential V→I pairs are never removed by any rule.
- Events with metric weight ≥ 0.8 (downbeats) always survive to background.

**Output:** A `ProlongationNode` tree. The root is the first background node; subsequent background nodes are chained as its children; each background node holds its middleground span as children; each middleground node holds its foreground span.

---

### 4.5 Data layer (`src/data/`)

**`sequence_extractor.py`** — Runs the full analysis pipeline on a `Score` and returns a list of event dicts. Each dict contains chord token, function token, key token, onset, duration, metric weight, and roman numeral label. Also implements `augment_sequences` (transposes each sequence across all 12 keys for data augmentation).

**`encoder.py`** — 90-token vocabulary:

| Range | Count | Description |
|---|---|---|
| 0 | 1 | PAD |
| 1 | 1 | START |
| 2 | 1 | END |
| 3–62 | 60 | Chord (12 roots × 5 qualities: major, minor, dim, aug, dom7) |
| 63–65 | 3 | Harmonic function (Tonic, Predominant, Dominant) |
| 66–89 | 24 | Key (12 tonics × 2 modes) |

Chord token formula: `3 + root × 5 + quality_idx`. Non-canonical qualities are collapsed before encoding: `major7 → major`, `minor7 → minor`, `dim7/half-dim7 → diminished`. `AMBIGUOUS` function maps to `TONIC` (index 0) for the 3-class model.

**`dataset.py`** — `HarmonyDataset` wraps sequences as PyTorch tensors (input = sequence[:-1], target = sequence[1:]). `build_datasets` performs 80/20 train-validation split.

---

### 4.6 Models (`src/models/`)

**`baseline_lstm.py`** — `BaroqueHarmonyLSTM`: a 2-layer LSTM next-chord prediction model.

```
Embedding(90, 64, padding_idx=0)
  → 2-layer LSTM(input=64, hidden=128, dropout=0.2)
  → Linear(128, 90)
```

Input: `(batch, seq_len)` token ids.
Output: `(batch, seq_len, 90)` raw logits.
Loss: `nn.CrossEntropyLoss(ignore_index=0)` (ignores PAD tokens).

**`train.py`** — Training loop with Adam optimizer, learning rate scheduling, and early stopping on validation loss. Saves the best checkpoint to `model_best.pt`.

---

### 4.7 Evaluation (`src/evaluation/`)

**`metrics.py`** — Evaluation functions:

| Function | Description |
|---|---|
| `next_chord_accuracy` | Top-1 accuracy on chord token prediction |
| `function_accuracy` | Accuracy on harmonic function (T/PD/D) |
| `perplexity` | Exp(mean cross-entropy) |
| `transition_validity_rate` | Fraction of predicted transitions present in training data |
| `build_transition_matrix` | Observed chord bigram counts |
| `random_baseline` | Random-model metrics for comparison |
| `evaluate_all` | Runs all metrics; returns a summary dict |

---

### 4.8 Analysis (`src/analysis/`)

**`embedding_analysis.py`** — Unsupervised analysis of the trained model's chord embedding space.

| Function | Description |
|---|---|
| `extract_chord_embeddings` | Pulls the 60 chord rows from `model.embedding.weight` → `(60, 64)` array |
| `reduce_dimensions` | PCA or UMAP projection to 2D (StandardScaler applied first) |
| `cluster_embeddings` | K-Means for k ∈ {3, 5, 7} |
| `compute_cluster_purity` | Cluster purity + Adjusted Rand Index (ARI) against majority-vote function labels |
| `compute_tonal_distance_correlation` | Pearson correlation between pairwise cosine distances in embedding space and pairwise circle-of-fifths distances (Mantel test approximation) |

Circle-of-fifths position: `(root × 7) % 12`. Circular distance: `min(d, 12-d)`.

The near-zero tonal correlation and low ARI values indicate that the LSTM embeddings have **not yet learned tonal structure in a geometrically interpretable way**. This is expected at the baseline stage and motivates future architectural improvements (attention, larger corpus, dedicated harmonic positional encoding).

## 6. Key design decisions

| Decision | Rationale |
|---|---|
| `fractions.Fraction` for all time values | Eliminates floating-point rounding in onset/duration arithmetic |
| `separate_voices=False` for solo MIDI | MuseScore exports monophonic pieces as 3–4 MIDI tracks; flattening to voice 0 avoids ghost voices |
| Geometric-mean chord scoring | Balances coverage and completeness; 7th chords win only when all 4 notes are present |
| Secondary dominant detection via `(root+5)%12` | Flags V/x only when quality differs from expected diatonic quality for that degree |
| Cadential V→I protected from reduction | Preserves structural cadences through all Schenkerian reduction passes |
| Metric weight ≥ 0.8 survives to background | Downbeat events are structurally privileged in the Ursatz |
| AMBIGUOUS function → TONIC (0) | Simplifies to 3-class model for encoding/evaluation |
| Majority-vote function labels for embeddings | Each chord token gets the function it most frequently held across the training corpus |

## 7. Running the project

### Install

```bash
git clone <repo-url>
cd bach-propagation
uv sync                    # runtime deps
uv sync --extra dev        # + pytest
```

### Run all tests

```bash
uv run pytest
uv run pytest --cov=src    # with coverage
```

### Full pipeline (scripts)

```bash
# 1. Extract harmonic sequences from a MIDI corpus
uv run python scripts/extract_all.py \
    --midi-dir data/samples/01_bach \
    --output data/sequences.json \
    [--augment]             # transpose to all 12 keys

# 2. Train the baseline LSTM
uv run python scripts/train_baseline.py \
    --sequences data/sequences.json \
    --epochs 30 \
    --checkpoint model_best.pt

# 3. Evaluate (LSTM vs. random baseline)
uv run python scripts/evaluate_baseline.py \
    --checkpoint model_best.pt \
    --sequences data/sequences.json

# 4. Analyse embedding space
uv run python scripts/analyze_embeddings.py \
    --checkpoint model_best.pt \
    --sequences data/sequences.json \
    --output-dir results/embedding_analysis

# 5. Validate pipeline on built-in BWV chorales
uv run python scripts/validate_chorales.py
```

## 8. Data

The project uses two data sources:

1. **music21 built-in corpus** — Bach chorales accessible via `corpus.search('bwv...')`. Used in `validate_chorales.py` and integration tests. No local files needed.

2. **Local MIDI corpus** — Bach solo works (Cello, Violin, Flute) available at [this Google Drive link](https://drive.google.com/drive/folders/1xVFWoCIXrHlDUlijDBDBJGywb6344sfT?usp=sharing). Place files under `data/samples/`. Tests that depend on local MIDI files skip gracefully when files are absent.
